# Диагностика Toyota Avensis через OBD-II

Программа для подключения к автомобилю через адаптер ELM327: читает коды
неисправностей, показывает параметры в реальном времени, снимает отчёт и
позволяет менять настраиваемые функции кузовной электроники.

Написана под конкретную машину — **Toyota Avensis, VIN `SB1BJ56L20E095222`**
(завод Бёрнастон, Великобритания), но работает с любым автомобилем,
поддерживающим OBD-II; специфика Toyota вынесена в отдельные модули.

## Что важно знать сразу

**Программу запускаешь ты, на своём компьютере, с воткнутым в машину
адаптером.** Я писал код, но подключиться к твоей Авенсис не могу — у меня
нет физического доступа к твоему железу.

Чтобы можно было всё пощупать до поездки в гараж, в комплект входит
симулятор: он изображает адаптер и автомобиль с типовым набором
неисправностей. Все команды ниже работают без машины, если не указывать `--port`.

## Установка

```bash
git clone https://github.com/ZanderDigoev/test.git
cd test
pip install -e ".[serial]"     # без [serial] — только Wi-Fi адаптеры и симулятор
```

Нужен Python 3.9 или новее. Зависимость `pyserial` требуется только для
USB- и Bluetooth-адаптеров.

## Быстрый старт

```bash
avensis scan                                     # на симуляторе, без машины
avensis --port /dev/ttyUSB0 scan --extended      # на реальном автомобиле
avensis --port /dev/ttyUSB0 web                  # то же самое в браузере
```

Если пакет не устанавливать, всё то же самое работает через
`python3 -m avensis`.

## Подключение адаптера

| Тип адаптера | Значение `--port` | Подготовка |
| --- | --- | --- |
| USB | `/dev/ttyUSB0`, `COM3` | в Linux добавить себя в группу `dialout` |
| Bluetooth | `/dev/rfcomm0` | привязать: `sudo rfcomm bind 0 AA:BB:CC:DD:EE:FF` |
| Wi-Fi | `tcp://192.168.0.10:35000` | подключиться к сети адаптера |
| Симулятор | `sim://` | ничего, это значение по умолчанию |

Разъём OBD-II на Avensis — под рулевой колонкой, слева от рулевого вала.
Для чтения достаточно включить зажигание в положение ON, двигатель заводить
не нужно.

## Команды

### Диагностика

```bash
avensis scan                          # полный отчёт: VIN, блоки, ошибки, стоп-кадр, параметры
avensis scan --extended               # плюс опрос ABS, SRS, кузовной электроники
avensis scan --markdown -o otchet.md  # отчёт файлом, чтобы показать мастеру
avensis scan --json                   # для обработки скриптом

avensis dtc --pending --permanent     # коды всех трёх категорий
avensis monitors                      # готовность систем самодиагностики
avensis freeze                        # параметры в момент фиксации ошибки
avensis vin                           # VIN и калибровки прошивок из блоков
avensis ecus                          # какие блоки есть на шине
```

`scan` и `dtc` возвращают код завершения `1`, если ошибки найдены — удобно
для скриптов.

### Графический интерфейс

Если консоль неудобна:

```bash
avensis --port /dev/ttyUSB0 web
```

Открывается на `http://127.0.0.1:8327`: состояние Check Engine, список ошибок
с расшифровкой и параметры, обновляющиеся сами. Страница целиком локальная,
интернет не нужен.

Сервер слушает только твой компьютер и пароля не имеет — открывать его наружу
(`--host 0.0.0.0`) не стоит. Сброс ошибок из интерфейса выключен, пока не
запустишь с `--allow-write`.

### Параметры в реальном времени

```bash
avensis live                                        # набор подбирается под мотор
avensis live 0C 0D 05 10                            # обороты, скорость, ОЖ, расход воздуха
```

Набор параметров по умолчанию зависит от двигателя: дизелю показываются
давление в топливной рампе, наддув и температура ОГ, бензину — лямбды,
топливные коррекции и угол опережения. Тип определяется по шине.

### Запись поездки и графики

Удобно ловить плавающие неисправности: те, что появляются только на прогретом
двигателе или под нагрузкой.

```bash
avensis --port /dev/ttyUSB0 log --duration 1800 -o poezdka.csv
avensis plot poezdka.csv
```

Журнал — обычный CSV с понятными заголовками, открывается в любой таблице.
`plot` строит из него самодостаточную HTML-страницу с графиками (без внешних
библиотек), причём участки, где горел Check Engine, отмечаются на всех
графиках сразу — сразу видно, при каких условиях он загорелся.

Записать и сразу построить: `log --duration 1800 --plot graf.html`.

### Двигатель

```bash
avensis engines                          # справочник моторов этого кузова
avensis --port /dev/ttyUSB0 engines --detect
avensis --engine 1CD-FTV scan            # если знаешь свой мотор точно
```

Код мотора по шине не передаётся, поэтому программа определяет только тип
топлива (по параметру 0x51 и признаку в байте мониторов) и показывает, какие
моторы с таким топливом ставились на этот кузов. Флаг `--engine` уточняет
подбор параметров и включает подсказку о типовых для этого мотора кодах.

### Сброс ошибок

```bash
avensis clear
```

Сброс стирает коды и стоп-кадры и **обнуляет мониторы готовности**. Пока
машина не откатает диагностический цикл, она не пройдёт инструментальный
контроль. Саму неисправность сброс не лечит — код вернётся.

## Изменение настроек автомобиля

Здесь нужно быть честным: **карты настраиваемых функций Toyota публично не
документированы**. То, что делает дилерский Techstream, опирается на закрытые
таблицы, привязанные к кузову, году и рынку. Взять их неоткуда, а записывать
байты по угаданным адресам — верный способ испортить конфигурацию блока.

Поэтому программа не притворяется, что знает адреса, а даёт инструмент, чтобы
найти их на **твоей** машине и потом безопасно применить.

```bash
avensis settings list                                   # каталог функций
avensis settings discover --ecu 740 --range 0100-01FF --save do.json
#   ... изменить функцию штатным способом (кнопкой, из меню, у дилера) ...
avensis settings discover --ecu 740 --range 0100-01FF --save posle.json
diff do.json posle.json                                 # отличие покажет нужную ячейку

avensis settings confirm auto-door-lock 0100            # закрепить найденное
avensis settings read auto-door-lock                    # текущее значение
avensis settings write auto-door-lock "выключено"       # проверочный прогон
avensis settings write auto-door-lock "выключено" --apply   # реальная запись
```

Что программа делает, чтобы это не закончилось эвакуатором:

- **без `--apply` ничего не пишется** — по умолчанию только проверочный прогон;
- **перед записью автоматически снимается резервная копия** ячейки в `~/.avensis/backups/`;
- **меняются только биты своей настройки** — соседние функции в том же байте не трогаются;
- **записанное перечитывается и сверяется** — если блок вернул не то, программа скажет об этом и напомнит путь к копии;
- восстановление: `avensis settings restore ~/.avensis/backups/748_*.json --apply`.

Подробный разбор процесса — в [docs/settings.md](docs/settings.md).

Про веб-интерфейс и запись поездки — в [docs/webui.md](docs/webui.md),
про устройство протоколов — в [docs/protocol.md](docs/protocol.md).

## Как это устроено

| Модуль | Отвечает за |
| --- | --- |
| `transport.py` | канал до адаптера: USB, Bluetooth, Wi-Fi, симулятор |
| `elm327.py` | AT-команды, выбор протокола, адресация |
| `framing.py` | разбор строк адаптера, сборка ISO-TP, контрольные суммы K-line |
| `obd.py` | стандартные сервисы OBD-II (режимы 01–0A) |
| `uds.py` | расширенная диагностика ABS, SRS, кузова (ISO 14229) |
| `dtc.py`, `pids.py` | расшифровка кодов и пересчёт параметров |
| `toyota.py`, `settings_ops.py` | адреса блоков Toyota и работа с настройками |
| `engines.py` | моторы кузова и подбор параметров под тип топлива |
| `triplog.py` | журнал поездки и построение графиков |
| `webui.py` | локальный веб-интерфейс |
| `vin.py`, `report.py` | разбор VIN и отчёты |
| `simulator.py` | виртуальный автомобиль с ездовым циклом для проверки без железа |

Программа поддерживает обе шины, встречающиеся на этом кузове: **CAN**
(ISO 15765-4) и **K-line** (ISO 9141-2 / ISO 14230-4). Какая именно стоит на
машине, определяется автоматически.

```bash
pip install -e ".[dev]"

```

178 тестов, включая сквозные прогоны против симулятора по обеим шинам и
поднятие настоящего HTTP-сервера для проверки веб-интерфейса.

## Границы применимости

- Полностью реализовано и проверено: чтение ошибок, параметров, стоп-кадра,
  VIN, калибровок, опрос блоков, сброс кодов, запись поездки, графики,
  веб-интерфейс.
- Определение двигателя ограничено типом топлива: код мотора (1CD-FTV и т.п.)
  по шине не передаётся, его можно только указать вручную.
- Реализован механизм, но требует подтверждения на конкретной машине:
  изменение настраиваемых функций (см. раздел выше).
- Не реализовано: расчёт ключа авторизации Toyota (`SecurityAccess`). Блоки,
  требующие авторизации, вернут отказ `NRC 0x33`. Алгоритм не публикуется;
  в `uds.py` для него оставлена точка подключения.
- Не поддерживается перепрошивка блоков — это осознанно за рамками проекта.

## Ответственность

Читающие команды безопасны. Записывающие (`clear`, `settings write`,
`settings restore`, а также сброс из веб-интерфейса при `--allow-write`)
меняют состояние автомобиля. Перед их запуском убедись,
что аккумулятор заряжен и адаптер не выдернется на середине операции.
Отключение штатных функций безопасности (например, напоминания о ремне) может
не пройти технический осмотр.
