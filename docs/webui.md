# Графический интерфейс и запись поездки

## Веб-интерфейс

```bash
avensis --port /dev/ttyUSB0 web
```

Открывает страницу на `http://127.0.0.1:8327`. На ней:

* состояние Check Engine крупно, чтобы было видно сразу;
* паспорт машины: VIN, тип двигателя, протокол шины, напряжение сети;
* список кодов с расшифровкой и пометкой категории (сохранённый,
  неподтверждённый, постоянный);
* параметры плитками, обновляются раз в полторы секунды.

Страница полностью локальная: ни одного внешнего файла, шрифта или скрипта.
Работает без интернета и в тёмной теме, если она включена в системе.

### Доступ и безопасность

| Что | Как устроено |
| --- | --- |
| Адрес прослушивания | `127.0.0.1` — виден только с этого компьютера |
| Пароль | отсутствует |
| Сброс ошибок | выключен, пока не запущено с `--allow-write` |
| Встраивание страницы | запрещено заголовком `X-Frame-Options: DENY` |

Флаг `--host 0.0.0.0` открывает сервер по сети. Пароля у него нет, поэтому
любой, кто до него дотянется, получит полный доступ к машине — включая сброс
ошибок, если запись разрешена. Программа предупредит об этом при старте.

```bash
avensis --port /dev/ttyUSB0 web --allow-write     # со сбросом ошибок
avensis --port /dev/ttyUSB0 web --http-port 9000  # на другом порту
```

Порт интерфейса задаётся флагом `--http-port`, а не `--port`: последний уже
занят выбором адаптера.

### Внутреннее устройство

Шина одна и последовательная, поэтому все обращения к адаптеру проходят через
замок: два одновременных запроса со страницы не перемешают обмен. Сервер
многопоточный только ради отзывчивости — сама шина всегда опрашивается по
очереди.

Адреса:

| Адрес | Метод | Что делает |
| --- | --- | --- |
| `/` | GET | страница |
| `/api/status` | GET | лампа, VIN, двигатель, протокол, напряжение |
| `/api/dtc` | GET | все три категории кодов с описаниями |
| `/api/live` | GET | текущие значения параметров |
| `/api/clear` | POST | сброс кодов; без `--allow-write` отвечает 403 |

## Запись поездки

Плавающие неисправности проще поймать не мгновенным замером, а записью: код
может появляться только на прогретом моторе, под нагрузкой или на конкретных
оборотах.

```bash
avensis --port /dev/ttyUSB0 log --duration 1800 -o poezdka.csv
```

Полезные флаги:

| Флаг | Смысл |
| --- | --- |
| `--interval` | пауза между замерами, по умолчанию 1 с |
| `--duration` / `--count` | сколько писать: по времени или по числу замеров |
| `--no-mil` | не опрашивать состояние Check Engine (чуть быстрее) |
| `--plot файл.html` | сразу построить графики |
| `--engine 1CD-FTV` | уточнить набор параметров под мотор |

Набор параметров можно задать и вручную: `log 0C 0D 05 23`.

### Формат журнала

Обычный CSV с человеческими заголовками — открывается в любой таблице.
Над заголовком лежат строки-комментарии с описанием сеанса и строка
`# meta:` с машинным описанием колонок (номер параметра, блок, единицы),
по которой строятся графики.

```
# автомобиль: SB1BJ56L20E095222
# протокол: ISO 15765-4 CAN (11 бит, 500 кбит/с)
# двигатель: 1CD-FTV — 2.0 D-4D, 116 л.с. (задан вручную)
# meta: [{"title": "Время (с)", ...}]
Время (с),Обороты двигателя [7E8] (об/мин),Скорость автомобиля [7E8] (км/ч),...
0.0,750,0,...
```

### Графики

```bash
avensis plot poezdka.csv -o graf.html
```

Получается самодостаточная HTML-страница: графики нарисованы встроенным SVG,
внешних библиотек нет, интернет не нужен. Под каждым заголовком — минимум,
среднее и максимум по параметру. Участки, где горел Check Engine, залиты
розовым на всех графиках сразу: видно, при каких оборотах, температуре и
нагрузке он загорелся.

## Проверка без машины

Всё перечисленное работает на встроенном симуляторе, причём не на постоянных
значениях: у виртуальной машины есть ездовой цикл — холостой ход, разгон,
движение с переменной скоростью, торможение, прогрев двигателя с 50 до 88 °C.

```bash
avensis log --count 140 --interval 0 -o proba.csv --plot proba.html
avensis web --allow-write
```
