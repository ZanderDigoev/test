# Как найти и изменить настройку автомобиля

Документ описывает, почему настройки нельзя просто «взять из таблицы» и как
их найти самому, ничего не сломав.

## Почему нет готовых адресов

Настраиваемые функции (автоблокировка дверей, задержка света в салоне,
поведение брелока) хранятся в памяти кузовного блока. Дилерский сканер
Techstream знает, в какой ячейке лежит какая функция, потому что у него есть
закрытые таблицы от производителя. Эти таблицы:

* не публикуются;
* различаются между кузовами, годами выпуска и рынками сбыта;
* различаются даже между комплектациями одной модели.

Записать байт по адресу, взятому «с форума», — значит с заметной
вероятностью попасть в чужую ячейку. Последствия варьируются от
неработающего стеклоподъёмника до блока, который перестал отвечать.

Поэтому программа поставляется с **каталогом функций без адресов**. Адрес
своей машины ты находишь сам — процедура ниже занимает минут двадцать и не
требует ничего, кроме адаптера.

## Метод сравнения дампов

Идея простая: снять слепок памяти блока, изменить функцию штатным способом,
снять слепок ещё раз и посмотреть, что поменялось.

### Шаг 1. Найти блок

```bash
avensis --port /dev/ttyUSB0 ecus
```

Команда покажет, какие блоки отвечают. Кузовная электроника обычно
откликается на адрес `740` (ответы приходят с `748`), комбинация приборов —
на `7C0`/`7C8`. Если по этим адресам тишина, посмотри весь список из вывода:
на разных кузовах адреса отличаются.

### Шаг 2. Снять слепок «до»

```bash
avensis --port /dev/ttyUSB0 settings discover --ecu 740 --range 0100-01FF --save do.json
```

Опрос только читающий и полностью безопасный. Диапазон можно расширить, но
каждый идентификатор — отдельный запрос на шину, так что `0000-FFFF`
займёт часы. Разумно начинать с `0100-01FF`, затем пробовать `0200-02FF`.

### Шаг 3. Изменить функцию штатным способом

Например, для автоматической блокировки дверей — так, как это описано в
руководстве по эксплуатации, либо попросить об этом на сервисе. Смысл в том,
чтобы блок сам записал новое значение в правильную ячейку.

### Шаг 4. Снять слепок «после» и сравнить

```bash
avensis --port /dev/ttyUSB0 settings discover --ecu 740 --range 0100-01FF --save posle.json
diff do.json posle.json
```

Отличие в одном-двух байтах и есть искомая ячейка. Например:

```diff
-  "0100": "01050200",
+  "0100": "02050200",
```

Здесь изменился младший полубайт первого байта ячейки `0100` — с `01` на `02`.

### Шаг 5. Закрепить находку

```bash
avensis settings confirm auto-door-lock 0100
```

Идентификатор сохранится в `~/.avensis/confirmed_dids.json` и будет
использоваться дальше. Если маска или номер байта в каталоге не совпали с
тем, что ты наблюдаешь, поправь запись в `avensis/data/settings.json` —
поля `byte`, `mask` и `values` описывают расположение поля внутри ячейки.

### Шаг 6. Пользоваться

```bash
avensis settings read auto-door-lock
avensis settings write auto-door-lock "выключено"            # проверочный прогон
avensis settings write auto-door-lock "выключено" --apply    # запись
```

## Что программа делает за тебя

| Защита | Как работает |
| --- | --- |
| Проверочный прогон по умолчанию | Без `--apply` на шину не уходит ни одного байта записи |
| Резервная копия | Перед записью содержимое ячейки сохраняется в `~/.avensis/backups/` |
| Точечное изменение | Читается вся ячейка, меняются только биты нужного поля, записывается обратно |
| Сверка после записи | Ячейка перечитывается; несовпадение — это ошибка, а не успех |
| Контроль сессии | Запись идёт в расширенной диагностической сессии, иначе блок откажет |
| Проверка длины | При восстановлении копия с другого блока отвергается по несовпадению длины |

## Если что-то пошло не так

```bash
ls ~/.avensis/backups/
avensis --port /dev/ttyUSB0 settings restore ~/.avensis/backups/748_20260818T113831+0000.json --apply
```

Восстановление сверяет VIN из копии с указанным через `--vin` и записывает
только те ячейки, чьё текущее содержимое отличается от сохранённого.

## Ограничение: авторизация

Часть блоков требует пройти процедуру `SecurityAccess` (сервис `0x27`):
блок выдаёт случайное число, тестер должен вернуть ответ, посчитанный по
секретному алгоритму. Алгоритм Toyota не публикуется, поэтому в программе
его нет — такие блоки ответят отказом `NRC 0x33`.

Точка подключения для собственной реализации:

```python
from avensis.uds import UdsClient

with UdsClient(elm, "740", "748") as uds:
    uds.security_access(level=0x01, key_from_seed=moy_algoritm)
```

## Формат каталога

`avensis/data/settings.json`, одна запись:

```json
{
  "key": "auto-door-lock",
  "title": "Автоматическая блокировка дверей при наборе скорости",
  "ecu": "Кузовная электроника (Body ECU)",
  "request_id": "740",
  "response_id": "748",
  "did": "",
  "byte": 0,
  "mask": "0x03",
  "session": "03",
  "values": { "выключено": 0, "при скорости выше 20 км/ч": 1 }
}
```

* `did` — идентификатор ячейки; в поставке всегда пустой;
* `byte` — номер байта внутри ячейки, считая от нуля;
* `mask` — маска поля внутри байта; сдвиг вычисляется автоматически;
* `values` — соответствие названий и значений поля (уже без сдвига).
